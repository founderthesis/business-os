ACTIONS (decision 394, the FAST/SLOW trial; spec docs/proposals/zoya-split.md). An action is one obligation of yours on an Engagement: a Zoya segment of Next action, or a substantive ask owed an answer on a thread linked to the row. Its key is "<engagement page id>:<type>:<origin>:<raised ISO timestamp with offset>". Origin: "msg-<Message-ID header>" (the inbound message that raised it), "call-<Activity or row id>" (Akshay's decision, his Your call, or the Activity that recorded it), or "seq-<routine>-<step n>" (a follow-up step); never derived from our own outgoing mail. Types and runs: reply, decision and hold are FAST's; followup (routines 1 to 6 and 8), nurture (routine 7, nurture, revival) and team (Jaya, Sarika, Ranjita, internal asks) are SLOW's. A Zoya segment carries its key in short form: "Zoya [<type> <origin> <raised ISO>]: <step>"; the engagement id is the row's.
- Old-format steps (no "[...]"): still yours by their wording and owner. Build the key at pickup from the row, the type the wording implies, the Activity or message that created it, and its Claude note date, and write it back onto that segment before acting, so the same obligation always gets the same key. Each run keys only the old-format steps of its own types (the type the wording implies decides the run), and only on rows it acts on this run, so two runs never key one step two ways. A Claude note date with no time keys as <date>T00:00:00+09:00.
- Reply owed means an unresolved substantive ask: a question, request or proposal from outside the team that no message from us has answered. Not owed: auto-replies, out-of-office, bounces, thanks or acknowledgements only, loop-ins, incidental Cc. An update with no ask gets only decision 404's bare emoji reply (Rules for Zoya), a FAST reply action, once per thread per 7 days. A holding reply or a loop-in answers nothing: the reply action stays open until the message that answers that ask, on the same thread.
- Before sending: look for the action key on an Activity (property "Action key"), then read the thread for a message from us after the action was raised that does what the action asks (the offer for an offer, the slots ask for a slots ask, the answer to that question). A later acknowledgement, holding reply, loop-in or unrelated mail is not a match. A match: send nothing, log the Activity if it is missing, complete the action. One message can complete several actions: one Activity, each action's completion line naming it.
- Send with the action key as email_compose idempotency_key (its SHA-256 hex if longer than 200 characters). Write "Action key" on the Activity only after a send receipt; an uncertain result leaves the action pending, retried with the same key after the thread check.
- WRITE PATH: every row write re-reads the row first and changes only this action's own segment of Next action, its own Waiting on entry and its own Claude note line; every other segment, owner and line stays as you found it, whoever wrote it.
